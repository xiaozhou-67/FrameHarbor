# 审查与后续运行验收

本清单供用户审查后执行，以下运行步骤在本次交付中均未执行。

## 先审查源码

- 阅读 README、设计说明和静态检查结果。
- 核对 `shared/validation.ts` 与 `shared/domain.ts` 的金额、身份、时间字段。
- 查看 `server/src/ticketing.ts` 与 `order-store.ts` 的事务、唯一键和状态迁移。
- 查看 `server/src/auth.ts` 的密码、会话、来源、CSRF 与管理员创建逻辑。
- 查看 `server/src/admin.ts` 的排片清场、影厅布局保护、整场取消补偿与审计。
- 确认 `.env.example` 未包含密码，`data/`、`dist/` 和 `.env` 未被本次交付创建。

## 首次启动和界面（后续）

1. 依据 README 配置管理员并启动开发环境，确认 8 部电影、3 家影院、6 个影厅及未来排片。
2. 在 1440px、768px、390px 宽度查看首页、电影详情、座位图与后台；座位图在窄屏可横向滚动。
3. 只用键盘访问导航、筛选、座位、表单和原生对话框，确认焦点可见、取消可用。
4. 检查类型、搜索、排序、即将上映、影院、日期、空态和断网重试。

## 身份、社区与权限（后续）

1. 注册普通用户，验证重复邮箱、短密码、错误密码及登录限流。
2. 未登录访问票夹和后台；普通用户尝试直接请求 `/api/admin/*`，应分别出现登录要求和 403。
3. 修改昵称与类型、加入/移出想看；查看推荐理由随明确偏好变化。
4. 提交至少 20 字影评；审核前仅本人可见，审核通过后公开并计入评分，修改后再次进入待审。
5. 缺少自定义请求头、缺 CSRF、错误 Origin 的写请求应被拒绝；另一个用户的订单 ID 应返回 404。

## 票务与竞争（后续）

1. 两个用户在不同浏览器选择同一场同一座位，同时下单；只应一个成功，另一个收到 SEAT_TAKEN。
2. 选择超出影厅的座位、重复座位、5 个座位，以及伪造总价字段，确认库存和价款仍由服务端控制。
3. 选 2 座使总额达到 ¥60，使用 FIRSTFRAME 应减 ¥10；第二单使用已付款优惠应失败。
4. 相同选座重复提交返回同一个待支付订单；更换座位时提示先处理旧订单。
5. 不支付并等待 8 分钟，刷新座位/订单后座位释放，订单 expired，优惠恢复；重启后也应如此。
6. 取消未支付单，座位与优惠立即释放；重复取消仍返回取消状态。
7. 演示支付确认后取得随机取票码；重复支付返回既有票码与金额。
8. 开场前 45 分钟以上整单退票，座位与优惠释放；不足 45 分钟或已核销时拒绝。
9. 开场前 15 分钟停止新下单；已创建且未过有效期的订单按保留时限完成支付。
10. 关闭 DEMO_PAYMENTS 后，前端禁用下单按钮，后端支付返回 PAYMENT_DISABLED。

## 后台一致性（后续）

1. 新增影片、影院、影厅、场次，查看用户端同步结果。
2. 同影厅新增重叠场次或不足 20 分钟清场间隔，收到 SHOW_OVERLAP；恰好满 20 分钟可排。
3. 影片有未结束排片时，修改时长或归档应被拒绝；已有排片的影厅改布局应被拒绝。
4. 创建待支付与已支付订单后取消未开场场次；确认待支付 cancelled、已支付 refunded、库存与优惠释放、审计存在。
5. 用票码搜索订单；在核销窗口内核销一次，重复核销幂等；核销后用户退票被拒绝。
6. 比对概览的有效已付款金额/票数、退款扣减、7 天按付款日统计与未来 7 天已售上座率。
7. 管理员读取影评后，作者在另一窗口编辑，再点旧卡片通过；应收到 REVIEW_CHANGED，新内容仍待审核，重新阅读后才可发布。
8. 在受控 HTTPS 反代中配置 TRUST_PROXY 与客户端地址转发，使用两个独立客户端确认限流额度按各自地址计数。
9. 选座报价暂时断网后恢复，点击「重新计价」保留原选座；保留座位请求进行中离开页面，成功后只出现票夹提示。

## 环境边界

- 当前后端是单实例 SQLite，不用于多个容器共享同一数据库文件。
- 生产环境需 HTTPS APP_ORIGIN；开发访问使用 127.0.0.1 与配置匹配。
- 排片日期与统计按北京时间处理，服务器和浏览器的操作系统时区不参与业务时间计算。
- 种子资料在首次空库时初始化一次，数日后需运营台继续排片。
