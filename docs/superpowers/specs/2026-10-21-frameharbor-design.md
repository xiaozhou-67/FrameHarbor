# 帧港 FrameHarbor 设计说明

## 目标与边界

以 D:/个人项目/FilmSys 的电影发现 → 影院排片 → 选座 → 订单，以及管理端的影片、影院、影厅、排片、评论、订单为业务基底，另建 D:/个人项目/FrameHarbor。用户授权自行命名、规划并在设计后直接实现。原项目保持原样。交付完整前后端源码、持久化模型、初始化演示内容、配置、操作文档及静态检查报告。只执行静态检查；不启动服务、不执行测试、不构建、不创建业务数据库。

## 原项目审计

- Vue 2、Webpack 3、Express 4 与分开的用户端、管理端；后端路由集中于一个文件。
- film_api/db/db.js 硬编码数据库账号密码；routes/index.js 对密码直接比对。
- getPhoneCode 返回验证码；updateScheduleSeat 接收客户端整份座位状态；order 接收客户端总价和用户 ID。这些接口边界需要重建。
- 不导入原 SQL 中的用户资料或密码，不复用原海报。保留上游 GPL-3.0 LICENSE 和出处，创作虚构影片及本地 SVG 海报。

## 方案比较与结论

1. 推荐：Vue 3 + TypeScript + Express 5 + Node 内置 SQLite，模块化单体。延续原技术路线，单目录即可交付；SQLite 使用单进程事务与唯一约束处理抢座，减少本地部署成本。
2. 原栈原地修补：变动较少，继续承担老依赖、三套工程与接口耦合成本。
3. 拆微服务并接入真实支付：运维和资质成本明显增加，超过本地项目审查目标。

选择方案 1；前端用户区和运营区共享设计系统，后端按认证、目录、票务、社区、管理拆分。运行环境 Node >=24.10.0，所有 npm 依赖锁定至 lockfile。原生 SQLite 采用 DatabaseSync，明确用于单实例本地/小规模项目。

## 产品与视觉

名称：帧港 FrameHarbor，标语「把今晚，留给大银幕」。深海黑、暖白、薄荷绿为主色，琥珀色标记评分；大字号标题、横向专题、海报网格、纸质票根和低饱和地图感影院卡片。桌面双栏、手机单栏；键盘焦点、可读对比、减少动态偏好、错误与空态完整。

用户页：发现首页、影片库（关键词/类型/上映状态/排序）、影片详情及评论、影院列表及详情、场次与选座、订单列表与票根、个人偏好与想看、登录注册。管理员页：营收与上座概览、影片增改/归档、影院影厅增改、排片及冲突校验/取消、订单筛选/核销、评论审核、审计日志。

## 业务契约

- 金额全程用整数分，服务端依据场次票价计算；每单 1–4 座，每用户同时只允许 1 个待支付订单。
- 座位网格以影厅行列为准；(show_id, seat) 唯一占用表，事务 BEGIN IMMEDIATE 内确认、占用、创建订单；客户端无权直接改库存。
- 待支付保留 8 分钟，且不超过开场时间；过期在每个票务读写入口惰性释放。支付、取消、退款均在同一事务中转换状态，重复同类操作返回已有结果。
- 支付明确为「演示支付」，由 DEMO_PAYMENTS 控制；无真实付款集成。优惠码 FIRSTFRAME：满 6000 分减 1000 分，每用户一次；未支付取消、超时和退款释放使用次数。
- 开场前 45 分钟以上可申请整单退款；开场 15 分钟前停止售票。核销仅对已支付且开场前 2 小时至结束后 30 分钟的订单开放。
- 影厅排片必须容纳影片时长 + 20 分钟清场，服务端检查时间交叉；营业场次禁止更改影片时长/影院归属/影厅尺寸等会破坏库存的属性。取消场次释放锁座、关闭未支付单并退款已支付单，留下审计。
- 评论每影片每用户一条，1–10 分，20–1000 字；提交后待审核，公开均分只计算通过审核的评论。精选指数与用户评分分开呈现。推荐按用户明确选择的类型与想看列表解释排序。
- 用户本人才能读取或变更自己的订单/偏好；管理员服务端鉴权；不提供危险的用户删除接口。

## 数据模型

users、sessions、movies、cinemas、halls、shows、orders、seat_claims、coupon_uses、watchlist、reviews、audit_logs；外键启用、WAL、busy_timeout、约束枚举和金额范围。schema.sql 独立维护，首次启动建表；seed 在空目录库时导入 8 部虚构电影、3 家影院和未来 7 天排片。管理员仅从环境变量创建，缺失密码不创建。

## 安全和错误处理

密码异步 scrypt + 随机 salt；会话随机 token 仅保存哈希，HttpOnly/SameSite Cookie；写接口限制 Origin、自定义请求头和 JSON，已认证写入校验 CSRF token。Zod 校验请求参数，SQL 参数绑定，分页上限，登录限流，Helmet，错误不暴露 SQL/堆栈。生产强制显式 APP_ORIGIN 与安全 Cookie，DEMO_PAYMENTS 必须显式启用。

## 验证与验收

自动静态：后端 tsc --noEmit、前端 vue-tsc --noEmit、ESLint、独立源码结构/导入/本地资源/占位与危险模式检查；只运行工具，不导入业务模块。人工静态审查事务、状态迁移、权限、排片重叠、时区、取消补偿、空态和异步竞态。文档单独列出后续运行验收步骤，记录未执行的运行验收范围。

## 设计自审

功能归属、API 数据格式、默认环境、状态机与价格来源明确；未采用真实支付、SMS、地图、外部推荐等需要外部账号的集成。演示资料标注虚构。时间以 UTC epoch 毫秒存储，业务时区 Asia/Shanghai，展示和日期筛选统一。
